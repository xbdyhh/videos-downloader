# 视频嗅探下载器（Chrome 扩展）

一个 Manifest V3 Chrome 扩展，可以识别当前网页中的视频与音频资源，并让你选择后下载。支持直接媒体文件、HLS (`.m3u8`) 分片合并、Bilibili DASH 音视频双轨合并、直播捕获以及 MP3/FLAC 音频提取，全部处理都在本机完成。

## 安装

1. 打开 Chrome，在地址栏输入 `chrome://extensions/`。
2. 打开右上角的“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择本项目文件夹。
5. 建议把扩展固定在工具栏。首次安装后，请刷新已经打开的网页。

## 使用

1. 打开含有视频的网页，必要时先点击播放几秒，让视频请求真正发出。
2. 点击工具栏中的扩展图标。
3. 勾选需要的视频，点击“下载所选”。
4. 普通媒体会直接交给 Chrome；HLS 会打开独立下载中心显示进度和控制按钮。
5. HLS 或格式转换完成后，点击下载中心的“保存文件”并选择保存位置。

### Bilibili

1. 安装或更新扩展后，刷新已经打开的 Bilibili 视频页面。
2. 正常播放视频，等待播放器加载出可用清晰度，然后打开扩展。
3. 在 `DASH` 资源中分别选择视频清晰度/编码和音轨。
4. 选择 MP4 或 TS 后点击“合并下载”；也可以选择 MP3/FLAC 后点击“仅音频”。
5. 下载中心会使用当前页面可播放的临时地址分别下载轨道，并通过本地 FFmpeg 合并或转换。

扩展只会使用当前账号实际有权播放的清晰度，不会绕过登录、大会员、付费内容或 DRM 限制。

每个资源旁边都可以选择“自动 / MP3 / FLAC”，然后点击“仅音频”打开下载中心：

- FLAC、ALAC、PCM 等无损源输出为 FLAC；
- MP3 源直接提取，不重复编码；
- AAC、Opus 等有损源输出为 MP3，码率不会高于可检测到的源码率；
- HLS 主播放清单含独立音轨时，优先使用默认音轨。
- 手动选择 MP3 或 FLAC 时，如果源编码不同，会先在本机完成转换再下载；格式相同时直接提取。

视频也可以选择“自动 / MP4 / TS”：

- 目标容器与源容器相同时直接保存；
- TS → MP4 优先使用 mux.js 无损重封装；
- MP4、WebM、TS 等容器不一致时，优先由 FFmpeg 无损重封装；
- 如果音视频编码不兼容目标容器，则转换为 H.264/AAC 后再下载。

## 能识别什么

- 页面中的 `<video>` 和 `<source>` 地址；
- 页面内显式指向 MP4、WebM 等媒体文件的链接；
- 动态加载的视频节点；
- 网络响应中返回视频 Content-Type 的资源；
- HLS (`.m3u8`) 播放清单，可自动选择最高码率并合并下载；
- HLS 主播放清单的清晰度选择，并自动折叠重复的子播放清单；
- HLS AES-128 加密、初始化分片和字节范围分片；
- HLS 下载进度、暂停/继续、取消、保存已下载部分；
- HLS 直播流持续捕获，可手动结束并保存；
- Bilibili 普通视频和番剧页面中的 DASH 视频轨、AAC/杜比/FLAC 音轨；
- Bilibili 清晰度、帧率、AVC/HEVC/AV1 编码及音轨选择；
- Bilibili 视频轨与音频轨下载完成后，使用本地 FFmpeg 无损合并；目标 TS 不兼容时自动转码为 H.264/AAC；
- MPEG-TS 中的 H.264/AAC 会使用本地 `mux.js` 无损重新封装为 MP4，不重新编码；
- 普通视频和 HLS 视频都可以仅提取音频，由本地 `ffmpeg.wasm` 输出 MP3 或 FLAC；
- 工具栏检测数量徽标、资源类型筛选和地址复制；
- 通用 DASH (`.mpd`) 播放清单（目前仅识别并标记）；Bilibili DASH 使用专用适配器下载。

## 已知限制

- `blob:` 地址通常是网页播放器临时生成的媒体流，不是一个可直接下载的文件。
- 普通 MPEG-TS 会优先转换为 `.mp4`；如果编码不兼容 MP4，会自动回退保存为 `.ts`。
- TS 转 MP4 会同时占用输入和输出内存，因此浏览器内转换限制为 750 MB。
- 音频提取需要额外的 FFmpeg 内存，源媒体限制为 500 MB；第一次进入编码阶段需要载入约 31 MB 本地 WASM 文件。
- 需要 FFmpeg 进行视频容器转换或编码时，源媒体限制为 500 MB。
- Bilibili DASH 的视频轨与音频轨合计限制为 500 MB，避免 ffmpeg.wasm 合并时浏览器内存不足。
- 无损重封装不会改变画质；H.264/AAC 转码会更慢，并可能产生轻微画质损失。
- 下载中心采用“生成文件 → 手动保存”两阶段流程，避免大型内存文件在 100% 后交给 Chrome 下载 API 时失败；取消保存位置选择后可以再次保存，无需重新下载分片。
- FFmpeg 使用随扩展打包的经典 Worker、Core 和 WASM 文件，不依赖远程模块加载。
- 把 AAC 等有损音频转换成 FLAC 不会提高音质，因此自动模式会选择 MP3；只有无损源才选择 FLAC。
- 手动把有损源转换为 FLAC 只改变保存格式，不会恢复已经损失的声音细节。
- 多音轨 HLS 目前只下载最高码率主播放列表中的媒体；独立外挂音轨不会另行混流。
- 下载过程中必须保持“视频下载中心”标签页开启。
- 通用 DASH (`.mpd`) 暂不支持分片合并；目前仅支持 Bilibili 专用 DASH 数据结构。
- DRM 加密视频（例如 Widevine）无法通过本扩展下载或解密。
- 某些站点需要登录 Cookie、特殊请求头或临时签名，直链可能过期或下载失败。
- Chrome Web Store、`chrome://` 等受保护页面不允许扩展扫描。
- 请只下载你有权保存的内容，并遵守网站条款与当地法律。

## 项目结构

- `manifest.json`：扩展声明与权限；
- `background.js`：网络资源识别与 Chrome 下载管理；
- `download.html` / `download.css` / `hls-downloader.js`：显示进度、控制任务、解密并合并 HLS 分片；
- `vendor/`：本地打包的 mux.js 和 ffmpeg.wasm 运行文件；
- `THIRD_PARTY_NOTICES.md`：第三方组件版本、来源与许可证说明。
- `content.js`：页面元素、动态节点和 Performance 资源扫描；
- `popup.html` / `popup.css` / `popup.js`：扩展弹窗界面。
